# Testing strategy

## Pyramid
| Layer | Tooling | What | Needs |
|---|---|---|---|
| Backend unit | pytest, FastAPI TestClient | config validation (incl. Phase 1 sources/RTSP/model cross-checks), settings, logging, error envelope, **wire protocol**, **detector geometry/NMS/thresholds on synthetic model output**, **file + RTSP source adapters (scripted fakes)**, **pipeline (frame skip, back-pressure, shutdown, cleanup, failure containment)**, **session lifecycle through the real API and worker WebSocket with a scripted fake worker** (idempotent start/stop, competing starts, timeouts, worker loss, relay, bounded queues, orphan recovery) | nothing; session tests use file-backed SQLite |
| Backend integration | pytest (`-m integration`) | Alembic upgrade/downgrade/round-trip incl. migration `0002`, model↔migration drift, ready/status against real PostgreSQL, pool hygiene | PostgreSQL (`TEST_DATABASE_URL`; `scripts\local-db.ps1` provides one) |
| Real model (`-m model`) | pytest | the downloaded YOLO face model on a public-domain photograph: finds the face, letterbox/resize alignment (IoU), two faces, no false positives on blank/noise frames, thresholds, determinism | the model file (`scripts\download-model.ps1`); **fails, never skips, when missing** |
| Live backend slice (`-m e2e`) | pytest | real uvicorn server + `WorkerAgent` + real model + real generated video over real sockets: full processing with exact frame/skip/processed counts, streamed boxes vs known face positions (IoU > 0.5, two faces), stop, unreadable video, worker death, model failure, missing model; real-OpenCV RTSP failure paths | model + OpenCV |
| Frontend unit/component | Vitest + React Testing Library | geometry (letterboxing, resize invariants), wire protocol, `LiveStream` (latest-wins decode, reconnect/back-off, no reconnect after end, cleanup), canvas drawing (recorded 2D calls incl. StrictMode regression), state copy (every state), monitoring page (preconditions, start/confirm/RUNNING, streamed frames, stats, stop, failures, polling convergence, re-attach, keyboard) | `fetch` and `WebSocket` faked per test |
| E2E | Playwright (Edge channel locally, Chromium in CI) | Phase 0 dashboard tests (stubbed API) + stubbed Live Monitoring states + **five `@live` tests against the real stack** (API + worker process + real model + embedded PostgreSQL): process a real video with pixel-level alignment of the drawn box, stop/restart, unreadable source, reload re-attach, consistency with the API | `e2e/global-setup.ts` starts and stops everything |

Playwright (+2 → 23): a real face is tracked end-to-end with the real model (stable id 1, details, canvas overlay toggle and selection highlight, counters, persisted counters, no visitor wording) and a reload re-attaches with a clean tracker numbering the next session from 1. Not covered by any test: accuracy on labelled real footage (none exists), RTSP, GPU.

## Phase 3 additions (recognition)
Four kinds of evidence are kept apart (see the benchmark): synthetic pipeline tests, labelled recognition benchmarks (LFW, run by scripts - not unit tests), controlled simulations, and real-video qualitative observations.
Backend (+112 → 389): `test_recognition_real.py` (6, **real models**: pinned checksums, alignment + embedding equal OpenCV's reference recogniser (cosine > 0.999; RGB/BGR convention), same face stays similar under darkening/scaling/blur and noise gives no embedding, quality gate rejects tiny/blurred faces, input validation, and the whole real pipeline – YOLO → tracker → recognition thread → `IdentityManager` on PostgreSQL – registers a face once, recognises it in a second session and after a process restart);
`test_identity_manager.py` (33, PostgreSQL: registration criteria, low quality, repeated detections, inconsistent observations, recognition across sessions/restarts, look-alike grey zone, clearly different person, ambiguity, model-version isolation, conflicts and hysteresis, same visitor on two tracks, two tracks of one unseen person, 8 racing threads, racing different people, two manager instances on one database, idempotent retry, duplicate/delayed messages, rollback of a failed or partially failed registration, invalid vectors, session persistence, erasure, retention, reconciliation);
`test_recognition_units.py` (43: alignment, quality gate and pose, embedding validation, index partitions, scheduler fairness/budget/monotonic sequence numbers, crop is a bounded copy, image store confinement/atomicity/untrusted payloads, observation parsing, wire format, config validation);
`test_recognition_relay.py` (12: fake worker → API → browser identity events, replay for late joiners, invalid/foreign/delayed observations, associations persisted before a session is finished);
`test_visitors_api.py` (18: every route needs a token, paging/sorting/search, no embeddings or paths in any response, image only through the authenticated endpoint, traversal attempts, erasure, recognition disabled); migration `0003` upgrade/downgrade/data-preservation/drift in `test_database.py`.
Mutation check on the identity manager: of eight deliberately introduced faults (no re-check under the lock, ignored ambiguity margin, no duplicate-id filter, grey zone treated as novel, single-observation recognition, same visitor on two tracks, mixed model versions, no self-consistency check) seven fail a test; the eighth is masked by the redundant registration re-check, by design.
Frontend (+31 → 184): `visitors.test.tsx` (15: skeleton, real records, thumbnails and the missing-image placeholder, empty state, error + retry, pagination, search, sort/order, accessibility, drawer details/history/link/Escape/error, erase only after confirmation), `recognition.test.tsx` (17: label/colour/notification logic, canvas labels per identity state, notification deduplication, silent replay, other-session events ignored, chip/detail visitor, unavailable-recognition notice, nothing carried into the next session).
Playwright (+2 → 25): register → gallery with a real thumbnail → details → second session recognised without a duplicate → no embeddings/paths in the API → image needs a token → **application restart (API + worker)** → still there and still recognised; two different people become two visitors, a *different photograph* of one of them is recognised, search and erasure. Labelled fixtures: person A = the public-domain portrait; person B = two different LFW photographs (a research benchmark kept on D:, git-ignored; the second flow is skipped if it is absent and says so).
Totals this run: 389 + 184 + 25 = **598** (Phase 2: 453). The restart test needed harness work: teardown now also runs `scripts/stop_stack.py --sweep` so a restarted API/worker can never be left behind.
Known harness quirk: Starlette's TestClient can raise `CancelledError` when a browser socket is closed while the worker socket is still being served in a thread; only `test_recognition_relay.py` is exposed, it waits on counters and tolerates exactly that exception in one helper.

## What the mocked tests do and do not prove
Scripted workers, fake sockets and synthetic model outputs prove *logic and contracts*. They say nothing about
detection accuracy. Accuracy-relevant claims rest only on the `model`/`e2e` tests, and even those use one portrait
photograph (and a synthetic video made from it) - **no accuracy was measured on real footage**.

## Fixtures
* `make_settings` / `make_config` / `make_full_config` build isolated `Settings`/`AppConfig` (no `.env` read, tmp dirs).
* `sqlite_engine` - file-backed SQLite with the ORM schema for session-logic tests (per-thread pooled connections).
* `isolated_schema` - throw-away PostgreSQL schema `test_<hex>` via `search_path`; Alembic runs inside it; dropped afterwards.
* `api()` (session tests) closes every fake worker on exit, even when an assertion fails, so a failing test cannot hang the run.
* Test data: `backend/tests/fixtures/astronaut_nasa_public_domain.png` (NASA, public domain) and videos generated from it
  by `app.vision.sample_video` at test time. No other face imagery exists in the repository.

## Process hygiene
`pytest-timeout` (120 s) guards every test. Playwright's own `webServer` could not terminate process trees on this
Windows setup (it hung after the run), so `e2e/global-setup.ts` starts API + worker (`scripts/dev_stack.py`) and Vite
with output redirected to files and `global-teardown.ts` kills the whole tree via `scripts/stop_stack.py` (psutil).
The suite fails fast if ports 8000/5173 are already in use and leaves no processes behind.

## Determinism and external services
Tests never contact the hosted database: with `TEST_DATABASE_URL` unset the embedded local PostgreSQL starts automatically; a `TEST_DATABASE_URL`
equal to `DATABASE_URL`, or a hosted provider without `ALLOW_HOSTED_TEST_DB=1`, aborts the run (`tests/db_safety.py`). No internet is needed after dependencies and the model are downloaded.

## Quality gates (all must pass) - run with `scripts\check.ps1`
Model checksum, `ruff check`, `ruff format --check`, `mypy` (strict, tests included), `pytest` (all markers),
`eslint`, `tsc --noEmit`, `vitest`, `vite build`, `playwright test`.
